# Carbonyl Agent - July 2026

Carbonyl Agent is the browser automation layer in the portfolio. It lets agent workflows drive a browser-like runtime when a normal browser is too heavy or hard to control.

July was a focused maintenance month. The main win was runtime parity. The pinned Carbonyl runtime was brought forward to the public runtime cut used by the project. The release also cleaned up install fallback behavior, license checks, and a few brittle test paths.

## TL;DR

Carbonyl Agent did not add a large new feature set this month. It got more dependable. The runtime pin now matches the intended Carbonyl runtime. The public Docker fallback points at the maintained image. The license check can run with the needed credit path. Tests were adjusted so stale paths do not block the current release line.

## Highlights

**Runtime parity.** The agent now points at the current Carbonyl runtime used by the project. That avoids a split where one path tests an old browser runtime while another path expects newer behavior.

**Cleaner install fallback.** If the preferred runtime path is not available, the Docker fallback now points at the maintained public image. That gives users a clearer recovery path.

**License check work.** The July release made the license check less fragile. It also made sure the Carbonyl runtime credit path is covered. That matters because browser stacks often include deep dependency chains.

**Test cleanup.** A chronically failing prior-runtime regression leg was removed from the active path. The goal is not to ignore regressions. It is to keep the current release line tested against a durable and meaningful baseline.

## Features shipped

None this month. July was a reliability and parity pass.

## Fixes

### Runtime and install

The runtime pin was corrected so the QA path and the packaged runtime agree. The public fallback image was also refreshed. For a user, the outcome is simple. When Carbonyl Agent starts or falls back, it is less likely to land on an old or mismatched runtime.

### License and dependency checks

The license check was hardened so blank-line or whitespace differences do not fail it. The build also switched to a steadier way to install the check helper. The credit gap for the AGPL wheel path was closed.

### Tests

The prior-runtime test path was moved to a durable tag and a stale regression leg was dropped. One log-capture test was made more robust. That keeps the test suite focused on behavior that still tells the project something useful.

### Code quality

A small parser cleanup reduced repeat match arms in the `wreq` path. This is internal code quality, but it helps keep the runtime wrapper easier to maintain.

## Performance & reliability

Reliability improved through runtime alignment and test cleanup. No user-visible speed work is called out this month.

## Breaking changes & migrations

None this month.

## Releases

**v2026.7.0** shipped the July parity release. It brought the pinned Carbonyl runtime forward, refreshed the Docker fallback, repaired the license-check path, and cleaned up tests around the current runtime.

## Dependencies & security

The main dependency and security story is license visibility. The release ensures the runtime and its related packages have the needed credit path, and the check step can run without failing on format noise.

## Docs & developer experience

Documentation updates were small. The important developer change is that installs and tests now point at the intended runtime path. Developers spend less time sorting out mismatched local behavior.

## Tests & CI

CI became less brittle around license checks and old-runtime coverage. The current runtime path is now the main proof point for the July release.

## Cross-project impact

Carbonyl supports the browser-automation side of the portfolio. A steadier runtime helps AIWG and Sandbox work that needs browser control, and it keeps Pagenary or docs-driven browser checks from relying on stale runtime behavior.

## Known issues & open threads

This was a narrow maintenance month. Broader browser automation capability, fleet behavior, and fingerprint-corpus work remain separate tracks.

## What's next

Expect more work around runtime upkeep, install paths, test coverage, and packaging. The priority is keeping browser automation dependable enough for agent workflows.
