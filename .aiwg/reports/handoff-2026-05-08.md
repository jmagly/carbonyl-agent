## Critical context for next session

### Repo conventions

- Two remotes: `origin` (Gitea, `git.integrolabs.net/roctinam/...`) and `github` (`github.com/jmagly/...`). **Always push to both** after committing on main.
- `delivery: pr-required` is implicit (no `.aiwg/aiwg.config` `delivery` block). Branch-per-issue + PR for every change.
- Branch naming: `fix/<issue>-<slug>` or `docs/<issue>-<slug>`.
- Commits: conventional commits (`feat`, `fix`, `docs`, `ci`, `chore`, etc.). No AI co-author lines, no `Generated with Claude` footer.

### Gotchas

1. **`ci.yml` manual checkout is broken on PR events** — uses `GITHUB_REF_NAME` which Gitea sets to PR number, not branch name. PR CI will fail with `fatal: Remote branch <N> not found`. Doesn't block merging; main-push CI on the merged commit validates. Future cleanup target.
2. **AIWG hooks may regenerate AIWG.md** — even though we switched to direct-injection mode (cycle CLAUDE.md → inlined). If you see local `M CLAUDE.md` + `?? AIWG.md`, it's the post-`aiwg refresh` hook re-deploying. Reset and proceed.
3. **qa-phase1.yml** triggers only on PR/cron/dispatch — not on push to main. After merging a qa#NN, dispatch via `mcp__git-gitea__actions_run_write` to validate.
4. **Docker layer cache on titan** — qa-phase1.yml clones carbonyl-agent and builds qa-runner inline. Layer caching can hit even when source content didn't change as expected. If a fix doesn't seem to take, check whether `=> CACHED [...] COPY xorg.conf.d/` is hitting an old layer.
5. **`download_job_log` MCP tool** — saves to MCP server filesystem, not local. Use `curl` with `~/.config/gitea/roctibot-token` for full logs.
